## Decision on logging off (2026-11-27)

**Owner's home tests with alpha.16** (reported by the owner, 2026-11-27; exe hash and WebView2 version not recorded):

* Unsaved text, then "Abmelden" from the Start menu: the session ended at once, with no question.
* The same again through Ctrl+Alt+Del → "Abmelden": the session ended, and the unsaved text was gone.

On that computer Codex found `HKCU\Control Panel\Desktop\AutoEndTasks` = 1. With this setting Windows ends programs that hold a logoff. The editor's protection (alpha.10 to alpha.14) refuses the query and asks, which works only where Windows lets a program ask. The causal link for these two runs is likely but not measured.

**Owner's decision:** the protection stays as it is. There is no emergency copy or autosave at the end of a session. Saving one's work and shutting down properly are part of computing lessons, and the pupil is responsible for them. A real logoff is therefore no longer a requirement before pupils' files (SPECIFICATION.md 3.5, ACCEPTANCE.md F-12).

### 0.1.0-alpha.9 (2026-11-26): preview navigation and window lifetime

Program addresses percent-encode UTF-8 path segments. The preview binds its accepted load to a WebView2 navigation ID and a generation. Switching pages or projects finishes pending deferrals with an explicit empty response and discards queued reads for the old load. Every accepted load owns a separate cache. Project and scan generations also govern folder watch notifications and scan results.

Project file work and preview reads use separate bounded pools. Shutdown closes the window's task queue and completes preview deferrals on the window thread. Accepted writes drain. Running reads are asked to cancel and workers are joined after the window closes. The folder watcher follows project switches without a window-thread join and retries after a failure.

The window dispatches bridge messages after the WebView2 callback returns, including the four messages that open native file dialogs. Queued actions wait while a system dialog runs its nested window loop.

### 0.1.0-alpha.6 (2026-11-25): two breaks that meet stay two

Found by a review of alpha.5 (reproduced in `breaks.js`): in `a<CR>b<LF>c` with `b` deleted, the lone `CR` came to stand directly before the `LF`; saved, the two bytes are read as one `CRLF`, so after reopening, or after restoring that undo step, a line was missing. Now a lone `CR` is never written directly before an `LF` break: that `LF` is written as `CRLF` (`keepApart` in `ui/js/breaks.js`). The line before keeps its bytes; only the break of the changed line gains a `CR`, which is unavoidable, since no byte sequence means "CR, then LF" as two breaks. New criterion F-10. Tests: `tests/ui/breaks.test.mjs` (the case, and a random-edit test: 2000 files with random breaks and 25 random edits each, every raw text must read back as the same lines; both fail on alpha.5), `tests/ui/ui.test.mjs` "line breaks: two breaks that meet after a deletion are saved as two"; native F-10 in the table above.

### 0.1.0-alpha.5 (2026-11-25): own line breaks for every undo step and every save

Found by a review of alpha.4 (reproduced in Node and in the browser test): deleting a lone `CR` and undoing to an unsaved intermediate state could write `LF`, and a late save confirmation rebuilt the saved state from the text typed meanwhile, so returning to the saved text later gave `LF` instead of the `CR` on disk. Cause: breaks were known only for the text as read and as last saved; everything else was derived by comparing texts. Now the undo history stores raw texts, so every step keeps its own breaks (`ui/js/editor.js`), every save takes the raw text it sends, and its confirmation records exactly that without changing the current state (`ui/js/main.js`; `restore` and `remember` in `ui/js/breaks.js`). "Unsaved" now also means that a line break differs from the file. New criterion F-09; test hook `HSE_TEST_SAVE_DELAY_MS` in the test build. Tests: `tests/ui/breaks.test.mjs` (3 new), `tests/ui/ui.test.mjs` "line breaks: undo to an unsaved step and a late save confirmation keep a lone CR" (fails on alpha.4, passes now); native F-07 to F-09 in the table above.
